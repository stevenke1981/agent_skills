# 收藏、匯入與拖曳啟用

在每台 **Windows x64** 電腦的檔案總管開啟 `\\DVA3221\public_ssd\agent_skills`，雙擊 **Start-Manager.cmd**。程式與 Python 執行環境共用 NAS，不需逐台安裝 Python。瀏覽器開啟 `http://127.0.0.1:8766`，上方顯示正在操作的電腦。

1. 貼 GitHub 儲存庫、`tree/分支/資料夾` 或 `blob/分支/…/SKILL.md` 連結。可先收藏網址，或下載到待審區。也能選擇／拖入技能包 ZIP。
2. 點 **檢視原文**，核對用途、來源 commit、授權與相依工具。下載不會執行來源腳本。
3. 把卡片拖到 **此機 Codex** 或 **此機 OpenCode**。新下載的技能會先詢問是否安裝；確認後只建立帶來源路徑的小型入口，完整資源留在 NAS。
4. 重啟對應客戶端，讓它讀到新增入口。實際任務開始時會按需讀取 NAS 原件；腳本、模型、引擎、GPU、MCP 等相依環境仍需在執行的電腦可用。
5. 從客戶端區拖回 **NAS 收藏**，會停止此機啟用。小型入口移到客戶端目錄的 `nas-library-removed` 備份，原始封裝不變。可以再次拖入啟用。
6. 從收藏區拖到 **移除 NAS 收藏**，確認後移入共享回收筒。可從「查看回收筒」還原；NAS 物件與歷史保留。其他電腦已建立的入口保留，不會遠端刪除。

拖曳以外，每張卡片也有按鈕完成相同操作，方便鍵盤與小螢幕使用。

## 多台電腦與權限

每台電腦啟動同一份 NAS 程式，但管理服務只監聽自己的 `127.0.0.1`。在 A 電腦開啟的是 A 的 Codex／OpenCode；B 電腦同樣開啟 NAS 啟動檔即可管理 B。不需開防火牆、設定 NAS 網頁伺服器或逐台複製技能包。

收藏、匯入與回收筒會寫入共享 NAS，需要該電腦目前帳號已有共享寫入權限。原有 `index.html` 與 `Search-Skills.ps1` 仍能供唯讀使用者查找。管理工具不修改 NAS ACL、客戶端設定、既有 Skill 或外部帳號。

`Setup-Codex-OpenCode.cmd` 提供一次建立總查找入口的方式；拖曳介面則讓每台電腦選擇自己的專門入口。通常啟用一個領域總入口即可，不必一次啟用整套幾十個子技能。

## 來源與版本

GitHub 匯入只接受公開 `github.com` HTTPS 連結，下載固定 commit 的 ZIP。不讀取登入憑證、不處理私人儲存庫；API 達到限制時可自行下載 ZIP 匯入。分支名稱包含 `/` 時，請改用 commit SHA 連結或 ZIP；選定單一資料夾時只收錄該資料夾，跨資料夾資源請改用儲存庫根目錄連結。

同一完整內容不會重複收錄；更新 commit 若內容改變會成為新版本，已啟用入口繼續指向原本版本。新版本下載後需另行確認啟用。GitHub 內指向同一 ZIP 普通檔案的別名會轉為普通檔案；外連、鏈式連結、ZIP 路徑穿越與特殊檔案會拒絕。

匯入大小上限 64 MiB、展開 256 MiB、6000 個檔案。偵測到常見憑證檔、未完成內容或不合格 frontmatter 的技能會保留待修資料，阻止啟用；這些檢查不等於完整程式碼或指令安全審查。

## 保存與復原

- `manager-state/library.json`：匯入版本、收藏網址、使用者批准與共享回收筒。
- `manager-state/history/`：每次共享狀態變動的完整 JSON；跨電腦用排他鎖與原子切換避免互相覆蓋。
- `objects/`：固定內容的完整來源；匯入後逐檔 SHA-256 讀回驗證，啟用前再檢查資源。
- `runtime/`：已核對官方下載 SHA-256 的 Python 3.13.16 Windows x64 可攜環境與 PyYAML 6.0.3 純 Python 模組，附原授權及逐檔清單；啟動前核對清單。
- `%LOCALAPPDATA%\NAS-Skills-Manager`：此電腦的啟動記錄，沒有來源內容或操作 token。

已被人工改動、來自其他工具、或含額外檔案的入口不會自動覆寫或移除。若程序意外中斷留下 `manager-state/.write.lock`，先確認各電腦的管理程序皆停止，再將鎖改名留存後重新啟動；不要直接刪除物件或歷史。用工作管理員依 `manager_server.py` 命令列識別並結束本機服務即可關閉；沒有設定登入自啟動。

維護者重建共享執行環境可使用 `python -X utf8 scripts/prepare_runtime.py`，需已有 PyYAML 6.0.3；普通客戶端不執行這個步驟。
